---

A **Body** (see `CONTEXT.md`) is render-only: a skinned mesh whose bones are placed on the solved Skeleton's joints every frame. The Skeleton never changes to suit a model; the model is built to the Skeleton.

The model is **generated by a Python script** run in Blender over the Blender MCP, never hand-modelled: the script is the source of truth, so the model can be regenerated when the Skeleton or the look changes. `art/build_female.py` is the worked example; read it before starting.

## Steps

1. **Read the contract.** `data/skeleton.json` (bone lengths) and `src/render/bodyRig.ts` (`restJoints`, `BODY_BONES`, `boneFrames`). The rest pose and bone list there are what the model must match. Done when you can list every bone's head and tail joint.

2. **Build the generator** as `art/build_<body>.py`. For a second model, first move the shared helpers out of `build_female.py` (materials, `tube`, `sphere`, `part`, weighting, armature, export) into a shared module both scripts import, and leave only the body shapes in each script. Done when running it in Blender produces `<Name>` + `<Name>Rig` and reports a triangle count.

3. **Look at it, and iterate.** Render shots with `art/render_views.py` (front, 3/4, side, back, head close-up) and Read the PNGs; the UI screenshot is too small to judge. Fix, re-run, re-render. Done when every view matches the reference and the count is within budget (5000 triangles).

4. **Pose-test the weights in Blender.** Rotate pose bones (lift a thigh about 50° and bend the knee 80°, twist the spine 25°, bend an elbow) and render. Done when no joint collapses, no part pulls away, and no clothing gets punched through badly; then clear the pose.

5. **Export.** Running the script with `SAVE = True` writes `art/<body>.blend` and `public/models/<body>.glb`. Done when the .glb's skin lists exactly the `BODY_BONES` names (parse the GLB's JSON chunk with node).

6. **Register it.** Add it to `Body` and `MODEL_FILES` in `src/render/bodyModel.ts` and to `defaultBody`'s URL parsing; update the Body entry in `CONTEXT.md`. Run `npx tsc --noEmit` and `npx vitest run src/render`.

7. **See it in a Match.** `preview_start` `dev`, open `/sword/?body=<body>`, click Start Match, screenshot during an attack. Done when both Fighters show the model, in Team colours, with swords in their hands, and the console shows no errors.

## Conventions the code depends on

- **Rest pose:** legs straight down (so the pelvis is at `ankleHeight + shin + thigh`, above the in-game 0.95), T-pose arms straight out at chest height, toes 0.14 in front of the ankle on the floor.
- **Axes:** in Blender the character faces **-Y** with its **left on +X**. The glTF export (`export_yup`) turns that into +z forward and left on +x, which is the game's facing 0.
- **Bones** run joint to joint, named as in `BODY_BONES` (`upperArm_L`, `shin_R`...): use `_L`/`_R`, because three.js strips dots from node names. `hips` runs from the pelvis downward; `spine` runs pelvis→chest; `head` runs chest→head joint. Bone roll is free: `BodyRig` measures each bone's own bind rotation.
- **The hips do not twist** with the torso in the Skeleton (the hip joints ignore lean and twist), so weight the lower torso, the skirt and the belt to `hips` and blend into `spine` above the waist.
- **Team colour:** the material whose name ends `_Skirt` is tinted with the Fighter's colour in `loadBodyModel`. A new model must name exactly one Team-coloured material that way, or that function needs changing.
- **Materials** are flat colours (no textures); `loadBodyModel` swaps them for Lambert materials and keeps the colour and double-sidedness. Mark any open surface (a skirt, hair cards) double-sided: `use_backface_culling = False` exports as `doubleSided`.

## Gotchas learned the hard way

- `execute_blender_code` must set `result` to a **dict**. Run scripts with `exec(open(path).read(), {"__file__": path})` so they can find the repo.
- In `tube`, ring axes are built as `u = v × axis` so the faces point outward. A mirrored (right-side) part flips winding: reverse its faces (`part(..., mirror=True)` does this).
- **Distance-only weights fail on the hand:** the palm is nearer the forearm bone than the hand bone. Use an explicit blend along the limb (`smooth(...)`) wherever a bone is short.
- Under the skirt, nothing shows: let parts intersect there rather than spend triangles joining them. A skirt over lifted thighs needs strong thigh weights (about 0.85 at the hem) or the leg pokes through.
- Head: keep the neck's top ring inside the jaw's taper, or the junction looks jagged. A 12×9 sphere plus a pushed-out nose vertex and two small eye spheres is enough at game distance.
- The skinned mesh's bind-pose bounds are wrong once its bones move it about the Arena: `frustumCulled = false` (already set in `loadBodyModel`).
- In the full `npx vitest run`, a few sim/net tests can time out under load (for example with a dev server running). Re-run them on their own before blaming the change.
